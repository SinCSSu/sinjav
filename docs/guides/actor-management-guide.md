# 演员管理使用指南

面向使用者：怎么让演员库自动长起来、怎么给演员补头像、名字写法不一致时怎么办。

> 相关文档：设计与实现细节见 [`docs/plans/2026-11-23-actor-management-design.md`](../plans/2026-11-23-actor-management-design.md)，
> 接口契约见 [`docs/openapi.yaml`](../openapi.yaml)（tag `actors`）。

---

## 1. 快速开始

### 1.1 首次使用（约 3 分钟）

1. **登录**系统（首次启动会要求设置用户名与密码）。
2. *（可选）* 打开 **设置** 页填写 **Emby 服务地址 + API Key** —— 需要「同步 Emby 演员」「把头像推送到 Emby」时才要填；
   只用本地演员库可以跳过。
3. 进入侧边栏 **演员** 页，点击 **更新 Gfriends 索引**。
   - 这一步会下载 Gfriends 头像库的索引文件（约 6.5 MB，10 万+ 条），**首次需要 1-2 分钟**，请耐心等待；
   - 成功后会提示「Gfriends 索引已更新，共 N 条」；
   - 索引是头像匹配的唯一依据，**不更新索引基本抓不到头像**。索引 7 天内不会重复下载（可由 `sinjav.gfriends.sync-threshold-days` 调整）。
4. 正常去 **刮削影片**（影片库 → 刮削）。刮削完成后，**本次新出现的演员会自动补头像**，无需手动操作；
   补全在后台任务里跑，可继续使用其它页面。

> 网络提示：Gfriends 索引与头像都从 GitHub 下载。若「更新 Gfriends 索引」失败，请先在 **设置 → 刮削代理**
> 填好 `proxy-host` / `proxy-port`（`sinjav.gfriends.enable-proxy=true` 时头像下载也走同一代理）。

### 1.2 日常使用（自动化部分）

| 场景 | 需要做什么 |
|---|---|
| 批量刮削影片 | 什么都不用做：新演员自动入库 + 自动补头像（受「自动补全」开关控制） |
| 在 Emby 里重新刮削某部影片 | 什么都不用做：回写的演员会并入本地演员库，新演员自动补头像 |
| 首次从 Emby 导入演员 | 演员页点 **同步 Emby 演员** |
| 老演员没头像 / 头像过期 | 演员页点 **补全头像**（只处理无头像的演员） |

## 2. 功能使用

### 2.1 演员列表

- 打开侧边栏 **演员**：头像网格展示全部演员，卡片下方是名字（鼠标悬停显示「名字（规范名）」），右上角为关联影片数。
- **搜索**：顶部输入框，支持演员名、规范名、别名（例如输入 `あいか`、`梦乃爱华` 都能搜到同一人）。
- **过滤**：`全部` / `仅有头像` / `仅无头像`；配合「补全头像」可快速定位缺头像的演员。
- **分页**：默认每页 20 位（接口上限 200）。
- **查看详情**：点击卡片打开详情弹窗 —— 左侧大头像，右侧规范名、别名、影片数、所属影片（点影片可跳到影片库）。

### 2.2 编辑别名（提高匹配率的关键）

为什么需要别名：Gfriends 头像库里的文件名是**日文原名**（如 `夢乃あいか.jpg`），而刮削站点有时给的是中文名
（`梦乃爱华`）或英文名（`Aika Yumeno`）。把各种写法登记为别名后，系统就能匹配到同一张头像。

操作步骤：

1. 演员页点开某位演员的详情；
2. **别名** 区域：第一个高亮标签是 **规范名**（＝Gfriends 匹配名 + 头像文件名），后面是普通别名；
3. 在输入框输入写法，回车添加；点标签上的 `×` 删除；点 **保存** 生效；
4. 保存后如果该演员还没有头像，点 **重新抓取头像** 立即按新别名再试一次。

要点：

- **规范名**尽量填成 Gfriends 里的日文名（如 `夢乃あいか`），这样照片文件名也是这个名字，便于人工核对；
- 别名是**全局唯一**的：同一个写法不能同时属于两位演员，冲突时保存会提示「别名已被其他演员占用」；
- 保存别名不会自动重抓，需要按上一步手动触发（或等下次批量补全）。

### 2.3 批量补全头像

1. 演员页右上角 **补全头像**；
2. 弹出「任务进度」窗口：显示 `已完成/总数`、失败明细，可点 **停止任务**（当前这位抓完后停止）；
3. 点 **后台继续** 关闭窗口，任务照常在后台跑；随时回演员页看头像是否出现；
4. 只处理**当前没有头像**的演员（有头像的不会被覆盖）；想换掉某位的头像，用详情里的 **重新抓取头像**。

抓取速度：每位演员间隔 1.5 秒（`sinjav.actors.scrape-interval-ms`，防风控），100 位演员约 2-3 分钟。

### 2.4 单个演员重抓

详情弹窗 **重新抓取头像**：按「规范名 → 别名」顺序重新匹配并下载，**会强制重下并覆盖已有头像**
（旧文件自动清理，所以规范名改过之后点它即可让头像文件名跟随新名字）。结果提示：

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 下载成功 | 已保存并回写路径 | — |
| 已存在，跳过 | 本地已有头像且文件在（只出现在批量补全/自动补全里，重抓按钮不会出现该提示） | — |
| 未找到 | Gfriends 索引里没有该名字 | 检查规范名/别名拼写，或更新索引 |
| 下载失败 | 网络失败或图片校验不通过 | 检查代理/网络后重试 |

### 2.5 Emby 集成

- **同步 Emby 演员**：遍历「Emby 媒体库同步」得到的条目快照（`emby_items` 里已识别出番号的条目），
  读取每个条目的演员列表，归一化后并入本地演员库，并记住演员在 Emby 的 `Person Id`。
  同步完成后，本次新增的演员会自动补头像。
  前提：先在 **设置** 配好 Emby，并在影片库工具栏点过 **同步 Emby 库**（否则没有条目快照，同步结果是 0 条）。
- **推送头像到 Emby**：头像下载成功后，若该演员已有 `Person Id` 且 `sinjav.actors.push-to-emby=true`，
  会自动把头像推到 Emby 的 Person 主图（尽力而为，失败只记日志，不影响本地头像）。
  详情弹窗里的「推送到 Emby」按钮目前仅作占位（后端接口未实现，点击会提示「开发中」）。

## 3. 常见问题（FAQ）

### Q1. 为什么有些演员没有头像？

按可能性排序：

1. **Gfriends 里确实没有这个人**（新人/素人很常见）——手工放一张图即可（见 Q2）；
2. **名字写法不一致**：站点给的是中文名，Gfriends 用日文名。把日文名填成**规范名**、其它写法加为**别名**（见 2.2）；
3. **索引太旧或没同步过**：演员页点 **更新 Gfriends 索引**；
4. **下载失败**：网络/代理问题，查看任务的失败明细（演员页任务进度窗口或任务列表页）；
5. **名字带空格/符号差异**：Gfriends 匹配是**精确匹配且区分大小写**（`Rino.jpg` 与 `RINO.jpg` 是两个条目），
   写法要与索引里的文件名完全一致。

### Q2. 如何手动上传演员头像？

系统没有上传按钮，把图片放进头像目录即可：

1. 找到该演员的**规范名**（详情弹窗顶部「规范名：xxx」；没有规范名时就是演员名）；
2. 把图片保存为 `data/actors/{规范名}.jpg`
   （Windows 默认：`<项目目录>\data\actors\夢乃あいか.jpg`）；
3. 回到演员页，打开该演员详情点 **重新抓取头像** —— 系统发现本地已有同名文件，会**直接登记**为头像，
   不访问网络、也不会覆盖你放的图（提示「下载成功」）；
4. 刷新演员页即可看到新头像。

补充：

- 扩展名请用 `.jpg`（`photo_path` 固定写成 `.jpg`）；
- 想换掉手工放的头像（改为 Gfriends 的图）：登记过一次后再点 **重新抓取头像** 即可强制重下覆盖；
- 自定义目录：改 `sinjav.actors.photo-dir` 后规则不变（文件名 = 规范名，放在该目录下）。

### Q3. 别名如何生效？

保存后**不会立刻重抓**。生效时机：

1. 该演员下次被补全头像时（详情里点 **重新抓取头像**，或批量 **补全头像**）；
2. 下次刮削同一演员的新影片时，`normalize` 会把新写法收敛到规范名，避免建出重复演员。

也就是说：别名既影响「头像匹配」，也影响「同一演员不会重复建号」。

### Q4. 头像和索引文件存在哪？怎么备份？

| 内容 | 位置（默认） | 说明 |
|---|---|---|
| 演员头像 | `data/actors/` | 文件名 = 规范名，直接拷贝即可备份/迁移 |
| 索引 | 数据库表 `gfriends_index` | 存在 `data/sinjav.db`（SQLite）；丢了重新点「更新 Gfriends 索引」即可 |
| 演员/别名/Emby Person Id | 数据库 `actresses` / `actress_aliases` | 同上，随数据库备份 |

### Q5. 「更新 Gfriends 索引」一直失败怎么办？

- 检查 **设置 → 刮削代理** 是否可用（GitHub raw 在部分网络下必须走代理）；
- 失败不会清空旧索引：已有索引仍可继续匹配，只是新演员可能缺头像；
- 首次同步（索引为空）失败时，演员页会提示失败原因，此时补全头像的任务会直接失败并记录「Gfriends 索引不可用」。

### Q6. 任务一直显示「运行中」/ 想中途停止？

- 任务进度窗口与 **任务列表** 页都能看到进度；演员补全每位间隔 1.5 秒，人多时耗时长是正常的；
- 点 **停止任务** 是「协作式取消」：当前这一位抓完后停止，已下载的头像保留；
- 应用重启会把残留的「运行中」任务标记为失败（启动恢复机制），不会永久卡住。

### Q7. 演员库里出现了不是 AV 演员的人？

演员只从两条路进来：**影片刮削结果的女优字段** 与 **Emby 条目快照里的演员**。
若 Emby 媒体库里混了非 AV 影片（且能识别出番号），就会被带进来。
处理办法：先修正/移除 Emby 里对应条目，再同步；本地演员目前没有删除入口（可用数据库维护）。

### Q8. 我把规范名改了，为什么照片文件名没变？

改规范名不会自动重命名已有文件（`photo_path` 仍指向旧文件，页面照常显示）。
想让文件名跟随新规范名：详情弹窗点 **重新抓取头像** —— 会按新名字重新下载并清理旧文件。

### Q9. 头像会不会覆盖我在 Emby 里手设的主图？

会。当 `sinjav.actors.push-to-emby=true` 且该演员已记住 `Person Id` 时，新下载的头像会直接推送为
Emby Person 主图。不想被覆盖就把该项设为 `false`（重启生效）。
